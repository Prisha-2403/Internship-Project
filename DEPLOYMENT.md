# Deployment

Three services, each free-tier:

| Piece | Host | Why |
|---|---|---|
| PostgreSQL | **Supabase** | Free tier does not expire, and holds the seeded demo dataset |
| FastAPI API | **Render** | Free Python web service, deploys straight from GitHub |
| React frontend | **Render static site** | Same account and blueprint as the API, so there is one dashboard to watch |

Both Render services are described in `render.yaml`, so a single Blueprint
import creates them together. `frontend/netlify.toml` is kept for anyone who
prefers Netlify — the build settings there are equivalent.

The three end up on different origins, which is why the session cookie is
configured `SameSite=None; Secure` in production — see step 2.

---

## Order of operations

The steps depend on each other, so do them in this order:

```
1. Supabase project        →  gives you DATABASE_URL
2. Migrate + seed          →  run from your machine against Supabase
3. Render API              →  needs DATABASE_URL, gives you the API URL
4. Netlify frontend        →  needs the API URL, gives you the site URL
5. Point CORS at Netlify   →  the API must be told which origin to trust
6. Verify
```

Step 5 exists because 3 and 4 each need the other's URL. The API goes up first
with `CORS_ORIGINS` unset, and is told about the frontend once it exists.

---

## 1. Supabase — the database

1. https://supabase.com/dashboard → **New project**. Name it `sentinel-finance`,
   pick the region closest to you, set a strong database password and save it.
2. Wait for provisioning (~2 minutes).
3. **Project Settings → Database → Connection string → URI**, and copy it.

It looks like:

```
postgresql://postgres.abcdefgh:YOUR-PASSWORD@aws-0-<region>.pooler.supabase.com:5432/postgres
```

Two edits before using it:

- Replace `[YOUR-PASSWORD]` with the real password.
- Append **`?sslmode=require`** — Supabase requires TLS.

Use the **Session pooler** connection (port `5432`), not the transaction pooler
(`6543`). The transaction pooler does not support prepared statements, which
SQLAlchemy relies on.

---

## 2. Migrate and seed — from your machine

The API on Render has no shell on the free plan, so schema and demo data are
loaded from here, pointing at Supabase.

```bash
cd backend

# Windows PowerShell
$env:DATABASE_URL = "postgresql+psycopg://postgres.xxx:PASSWORD@aws-0-region.pooler.supabase.com:5432/postgres?sslmode=require"

# Git Bash / macOS / Linux
export DATABASE_URL="postgresql+psycopg://postgres.xxx:PASSWORD@aws-0-region.pooler.supabase.com:5432/postgres?sslmode=require"

.venv/Scripts/python -m alembic upgrade head
.venv/Scripts/python -m scripts.seed_demo_data --transactions 12000
```

Note the driver prefix: `postgresql+psycopg://`, not plain `postgresql://`.

**12,000 rather than 40,000.** Supabase's free tier allows 500 MB and Render's
free instance has 512 MB of RAM; detection loads the transaction history into a
dataframe, and 12,000 keeps both comfortable while still filling every chart.

The seeder prints the demo accounts and writes their shared password to `.env`
as `DEMO_USER_PASSWORD` — you will need it in step 4.

Then commit the trained model so Render has it:

```bash
cp backend/artifacts/model_if-*.joblib backend/artifacts/model_deployed.joblib
git add -f backend/artifacts/model_deployed.joblib && git commit -m "Add deployed model artifact" && git push
```

Render's filesystem is ephemeral. Without the artifact the API silently falls
back to rules-only scoring, which would disagree with the scores already stored.

## 3. Render — the API

1. https://dashboard.render.com → **New → Blueprint**, select the
   `sentinel-finance` repo. Render reads `render.yaml`.
2. It will ask for the two values marked `sync: false`:
   - `DATABASE_URL` — the Supabase URL from step 1, with `postgresql+psycopg://`
   - `CORS_ORIGINS` — leave as `http://localhost:5173` for now; corrected in step 5
3. Deploy. First build takes 5–10 minutes (numpy, scipy and scikit-learn compile
   their wheels).
4. Confirm: `https://sentinel-finance-api.onrender.com/health` returns
   `{"status":"ok"}`.

`SECRET_KEY` is generated by Render and stays stable across deploys, so sessions
survive a restart.

**The free instance sleeps after 15 minutes idle.** The first request after that
takes ~50 seconds. See *Before the demo* below.

---

## 4. Netlify — the frontend

1. https://app.netlify.com → **Add new site → Import an existing project** →
   GitHub → `sentinel-finance`.
2. Netlify reads `frontend/netlify.toml`, so base directory, build command and
   publish directory are already correct. Do not override them.
3. Add environment variables under **Site configuration → Environment variables**:

   | Key | Value |
   |---|---|
   | `VITE_API_BASE_URL` | `https://sentinel-finance-api.onrender.com` |
   | `VITE_DEMO_ANALYST_EMAIL` | `analyst@sentinel.demo` |
   | `VITE_DEMO_SENIOR_ANALYST_EMAIL` | `senior.analyst@sentinel.demo` |
   | `VITE_DEMO_MANAGER_EMAIL` | `manager@sentinel.demo` |
   | `VITE_DEMO_ADMIN_EMAIL` | `admin@sentinel.demo` |

   No trailing slash on the API URL. These are compiled in at build time, so
   changing one requires a redeploy.

4. Deploy, and note the site URL, e.g. `https://sentinel-finance.netlify.app`.

---

## 5. Point the API at the frontend

Back in Render → your service → **Environment**, set:

```
CORS_ORIGINS = https://sentinel-finance.netlify.app
```

Exact scheme and host, no trailing slash, no path. Save; Render redeploys.

Without this the browser blocks every API call, and because credentials are
involved a wildcard origin is not an option.

---

## 6. Verify

1. Open the Netlify URL. The login page should render.
2. Sign in as `admin@sentinel.demo` with the seeded password.
3. The dashboard should show real counts.
4. Refresh on `/transactions` — it must stay on the page, not 404. If it does
   404, the SPA redirect is not being applied.
5. Open a CRITICAL transaction and confirm the risk factors sum to the score.

If sign-in fails but `/health` is fine, it is almost always one of:

| Symptom | Cause |
|---|---|
| CORS error in the console | `CORS_ORIGINS` does not exactly match the Netlify origin |
| Login succeeds, next request 401s | `COOKIE_SAMESITE` is not `none`, or `COOKIE_SECURE` is not `true` |
| Requests go to the Netlify domain | `VITE_API_BASE_URL` was missing at build time — set it and redeploy |
| 500 on every data endpoint | `DATABASE_URL` lacks `postgresql+psycopg://` or `?sslmode=require` |

## Before the demo

**Wake the API about five minutes ahead.** Render's free instance sleeps after
15 minutes idle, and the first request afterwards takes roughly 50 seconds —
long enough to look broken.

Open `https://sentinel-finance-api.onrender.com/health` in a tab and wait for
`{"status":"ok"}`, then load the site. Keep a tab open during the walkthrough so
it does not sleep mid-demo.

To avoid it entirely, point a free uptime monitor (UptimeRobot, cron-job.org) at
`/health` every 10 minutes.

---

## What is deliberately not here

No Docker or CI. The stack is small enough that three managed free tiers carry
it, and adding container builds before there is anything to orchestrate would be
weight without benefit. The tests run locally with `pytest`.
